## Вопросы владельцу

1. **Жалобы и анамнез (A6).** В `CompleteEncounterDto` нет таких полей, поэтому секции «Жалобы и анамнез» нет, бэкенд не менял. В FHIR R4 им соответствуют, например, `Encounter.reasonCode` / `Encounter.reasonReference` или `ClinicalImpression` (`description`, `finding`) / `Condition` с категорией «симптом/жалоба»; выбор и добавление полей в API за вами.
2. **Серверный черновик.** Нужен ли эндпоинт (например `PUT /encounters/{id}/draft`) чтобы черновик жил между устройствами и не оставлял клинический текст в браузере. Пока только локально: `localStorage` общего рабочего места хранит текст приёма до 3 суток; смягчено очисткой при выходе из системы, сроком жизни и отсутствием идентификаторов пациента.
3. **Когда показывать запрос при уходе со страницы (A8).** Сейчас только если локальный черновик не удалось сохранить. Если нужен запрос при любых несозданных на сервере данных, это одна строка в `use-encounter-draft.ts` (но врач увидит запрос при каждой перезагрузке, хотя данные не теряются).
4. **Недавние диагнозы врача (A7).** Список диагнозов именно этого врача из уже загруженных данных не собрать (нет эндпоинта «мои частые диагнозы»); показываю диагнозы пациента из его истории (первая страница, 10 приёмов), пока без счётчика частоты. Для «частых у врача» нужен агрегат на бэкенде.
5. **Справочник МКБ-10 в демо.** В снимке только 25 кодов МКБ-10, засеянных мной; в чистом окружении без `npm run seed:terminology` комбобокс теперь честно показывает «Справочник недоступен» с повтором. Заметка по сидеру: при первом запуске seed вывел «created…» и упал на проверке `$expand` для МКБ-10 (HAPI-2788, поиск по `url` ещё не проиндексирован), повторный запуск через ~минуту прошёл (в духе решения про готовность HAPI; сам сидер не менял).
6. **Название кода: «Показатель 1» в выпадающем списке** по-прежнему «20006 — Температура тела» (код НСИ впереди); в A9 речь была только про единицы, поэтому не менял. Предлагаю показывать название без кода, если вы согласны.
7. **Подсказка единицы по показателю** (например, температура → °C сразу) не сделана намеренно: комментарий `EMPTY_OBSERVATION` запрещает предустановку, чтобы не записать неверную единицу. Если справочник показатель→единица утверждён, это небольшая правка.
8. **Диагнозы теперь выбираются, а не вводятся свободно.** Текст, не ставший кодом, не отправляется (код пуст → «Выберите диагноз из списка»). Это согласовано с правилом сервера (код обязан быть в справочнике), но привычка «сначала название, потом код» теперь не работает.
