# TASK-005 — UX-аудит фронтенда: реестр проблем

Дата: 2026-10-26. Метод: ручной обход живого стека (`http://localhost:3000`) в Chrome на ширине 1440 px и 400 px за тремя ролями (пациент `patient.kuznetsov`, врач `doctor.ivanova`, админ `admin.demo`) и анонимно. Код не менялся, это только реестр для будущей реализации.

Правила: `AGENTS.md`, `.claude/DOD.md`. Визуал можно менять как угодно (это курсовой проект), главное — удобство. Задачи ниже не начинать без команды владельца.

## Принципы, по которым оценивалось

| Код | Принцип | Суть для этого проекта | Источник |
|---|---|---|---|
| P1 | Последовательное раскрытие (progressive disclosure) | Редкое и сложное — во второй уровень (свернуть, «Ещё», отдельная страница). Частое — сразу | [NN/g](https://nngroup.com/articles/progressive-disclosure/) |
| P2 | Сводка по пациенту на первом экране, идентификация в одном фиксированном месте | Врач должен с первого взгляда видеть, кто перед ним и что важно; так меньше ошибок «не тот пациент» | [NIST NISTIR 7741](https://nvlpubs.nist.gov/nistpubs/Legacy/IR/nistir7741.pdf), [обзор NIST по EHR](https://www.healthcaredive.com/news/nist-report-focuses-on-ehr-design-risks/407184/) |
| P3 | Обзор «одним взглядом» для планирования дня | Журнал и расписание врача — календарная сетка, а не списки | [NIST: EHR и рабочий процесс](https://www.fiercehealthcare.com/it/nist-offers-recommendations-for-integrating-ehrs-into-workflow) |
| P4 | Разрушительные действия отделены и защищены | Не рядом с частым действием, не равного веса; подтверждение по тяжести; не только цветом | [UX Movement](https://uxmovement.com/buttons/how-to-design-destructive-actions-to-prevent-data-loss/), [SSW rules](https://www.ssw.com.au/rules/destructive-button-ui-ux) |
| P5 | Закон Хика | Меньше равнозначных вариантов на экране — быстрее решение | [Laws of UX](https://lawsofux.com/index.md) |
| P6 | Закон Фиттса | Главное действие крупное и рядом с вниманием, липкие панели действий в длинных формах | [Laws of UX](https://lawsofux.com/index.md) |
| P7 | Эффект фон Ресторфф | Выделять одно главное (занятый слот, главный CTA), а не всё подряд | [Laws of UX](https://lawsofux.com/index.md) |
| P8 | Продуманные пустые состояния | Пустое состояние сообщает статус, подсказывает следующее действие и ведёт в задачу | [NN/g: empty states](https://nngroup.com/articles/empty-state-interface-design) |
| P9 | Видимость статуса системы, обратная связь | Успех, загрузка, «ничего не найдено» — явно; анимации 100–300 мс, только для смысла | [NN/g: empty states](https://www.nngroup.com/videos/empty-states-in-application-design-guidelines/), [сводка по длительностям](https://www.react.doctor/docs/rules/react-doctor/no-long-transition-duration) |
| P10 | Согласованность и язык пользователя (эвристики Нильсена) | Одинаковые компоненты одинаково выглядят; никаких внутренних ID и RRULE на экране | [NN/g](https://nngroup.com/articles/progressive-disclosure/) |

Важность: **H** — мешает основной задаче роли или риск ошибки; **M** — заметно ухудшает удобство; **L** — полировка.
