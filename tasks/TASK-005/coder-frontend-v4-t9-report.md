| **VE1 — переходы между страницами** | сделано | `components/layout/page-transition.tsx`, подключён в `<main>` трёх оболочек (врач/админ, пациент, публичная). Выбрана **CSS-анимация с ключом по `pathname`**, а не View Transitions API: в Next 15 `viewTransition` экспериментальный, обёртка над `router.push` пропустила бы back/forward и обычные `<Link>`, API есть не во всех поддерживаемых браузерах. Ключ `pathname` перезапускает анимацию в любом браузере без полифилов. Анимируется только `opacity` (200 мс, `ease-out`): `transform` на обёртке сделал бы её containing block для `position: fixed` (панель подтверждения записи, нижняя кнопка лендинга), и они «прыгали» бы на время анимации. «Подъём» даёт стаггер списков. Первая страница визита не анимируется. Шапка и сайдбар вне обёртки. |

Хук закрывает «окно» через 700 мс после появления данных (`isReady`), поэтому страницы пагинации, refetch и фильтры добавляют строки без анимации. Применено: записи пациента, уведомления, история визитов, назначения, журнал врача (таймлайн), история и назначения в карточке пациента, каталог врачей, все админские таблицы (`PaginatedTable`: и таблица, и карточки). Используется `backwards`, а не `both`, чтобы hover-подъём интерактивных карточек не конфликтовал с анимацией. |

## Открытые вопросы владельцу

1. **Слово «Лайфлайн» в шапке кабинета пациента скрыто на ширине < 480 px** (остаётся знак), чтобы поместились бургер, «Записаться» и колокольчик в одну строку. Если нужен всегда виден текст, придётся прятать «Записаться» в иконку.
2. **Тряска поля при ошибке не сделана** (см. выше). Нужна ли она вопреки a11y-риску?
3. **Публичный бургер справа** оставлен с правой шторкой, потому что кнопка справа. Если хотите единообразия, можно перенести кнопку влево, но шапка там и так плотная.
4. **Базовый hover-переход на всех ссылках/кнопках** при переключении темы даёт короткую (120 мс) плавную смену цвета только у этих элементов. Если заметно мешает, можно отключать переходы на время смены темы (отдельная маленькая задача).
5. **Карточка пациента при медленной загрузке** показывает «Загружаем…» под каждым из нескольких скелетонов (3 подписи). Можно оставить одну на экран, но это общее состояние загрузки страницы (отдельная задача).
6. **Поиск пациента (врач)**: при ошибке — строка «не удалось» без кнопки «Повторить» (поиск повторяется при следующем вводе). Добавить кнопку?
7. Бóльшие вещи не трогал: нижняя навигация (tab bar) для кабинета пациента вместо шторки; свайп-закрытие шторок; View Transitions для мастера записи (шаги и так анимируются `step-in`).
