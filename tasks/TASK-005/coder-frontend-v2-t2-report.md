## Открытые вопросы владельцу

1. **Откат вместо подтверждения.** Тост с кнопкой «Отменить» реализован и покрыт тестами, но пока ни одно действие его не использует: для неявки, отмены записи, отзыва согласия и удаления в API нет обратной операции. Единственное обратимое действие — деактивация пользователя (есть «Активировать»). По D2 для неё оставлено подтверждение; если хочется «сделано + Отменить», это изменение в одну функцию (`UsersPanel`).
2. **D1 полностью.** В ответе `GET /api/v1/admin/users` только ссылки `Patient/<id>` и `PractitionerRole/<id>`. Врач показан по специальности из каталога (список ограничен 100 врачами, дальше подпись «Врач» без специальности). «Медкарта №…» и «Кабинет 101» из аудита невозможны без расширения ответа (номер медкарты, кабинет роли): это решение по backend.
3. **Основное действие строки.** Выбрано «первый пункт меню», а не клик по строке (проще для клавиатуры и экранных дикторов). Если владельцу нужен клик по строке, это отдельная доработка `PaginatedTable`.
4. **Форма отзыва согласия врача** (`consent-revoke-form`, карточка пациента) ещё использует прежний «розовый» `danger`: она входит в T1 (макет карточки пациента); `Button variant="danger"` оставлен только ради неё.
5. **«Сгенерировать слоты»** на 1440 px переносится на две строки (узкая колонка действий). Можно сократить подпись до «Слоты…» или оставить; решение по тексту.
6. **Неиспользуемые строки i18n** (`editAria`, `deleteAria`, `deactivateAria`, `activateAria`, `usageAria` и т. п. у админ-таблиц) остались в каталогах: имена кнопок теперь задаёт «Действия: <кто>». Можно вычистить отдельным проходом.
7. **Тёмная тема, подпись «Неявка» в карточке журнала.** Бейдж `warning` лежит на заливке `warning-soft` самой карточки, поэтому читается как текст с иконкой без пилюли. Допустимо, но если нужна пилюля, надо менять фон карточки (T5, календарь).
