## Вопросы владельцу

1. **Кабинет/место приёма.** В публичном API нет названия кабинета: `Doctor.roomId` объявлен в DTO practitioner-service, но демо-данные его не отдают, а имя `Location` («Кабинет 101») доступно только через админские эндпоинты. Показываю только адрес клиники (из `home.contactAddressValue`). Нужно решение: добавлять в `GET /doctors` / слот / запись поле `roomName` (backend), тогда строка «Кабинет» добавляется в сводку и успех одним правком.
2. **Адрес клиники** лежит в i18n (`home.contactAddressValue`), а не в константе `CLINIC_CONTACTS` (там только телефон и email). Использовал i18n-значение как единственный источник; если нужна константа для .ics на любом языке интерфейса, адрес на английском попадёт в LOCATION при EN-интерфейсе.
3. **Группировка услуг** сделана по специальности врачей: это N запросов `GET /doctors?serviceId=` на шаге 1 (кэшируются 5 мин, шаг врачей их переиспользует; в демо — 6). Если нужна одна запрос-группа, понадобится поле `direction`/`category` у услуги в catalog-service.
4. **Правила отмены.** Показан только нейтральный текст без сроков, как просили; если у клиники есть реальный срок отмены, его нужно ввести как константу.
5. **Заголовок страницы `/booking`** («Запись на приём» / «Четыре шага — около двух минут») остаётся над экраном успеха; подзаголовок на этом экране лишний, но `BookingScreen` не знает о состоянии мастера. Оставил как есть.
6. **Демо-каталог:** у всех услуг по одному врачу, поэтому авто-пропуск шага врачей срабатывает почти всегда, а шаг врачей виден только по пути «Не знаю, какая услуга нужна» (там 4 врача с чипами). Это следствие данных, не ошибка.
7. **C1:** повторный запрос `no-store` делает страницу динамической только пока каталог пуст; после наполнения кэш работает как раньше. Вне фронтенда: кэш Redis на стороне сервисов (5 мин) пустые ответы по-прежнему может держать — не проверялось и не менялось.
