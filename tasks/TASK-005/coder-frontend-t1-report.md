## Вопросы владельцу

1. **«Продолжить приём» (A4).** Нужен серверный признак открытого приёма по записи: например `encounterId`/`hasOpenEncounter` в `AppointmentViewDto` журнала врача (6.5) или эндпоинт «приёмы по записи». Пока признак живёт в localStorage браузера. Демо-приём `1442` в этом браузере будет показан как «Открыть приём» (диалог про 27.10 предложит «Начать сейчас» и вернёт открытый приём).
2. **Аллергии, список диагнозов «активные/снятые», медкарта-номер** в API нет: в сводке они не показываются (не пишем «нет аллергий» без данных). Диагнозы названы «недавними», потому что история не знает, снят ли диагноз.
3. **Показатели** берутся только из самого свежего завершённого приёма (один дополнительный запрос `GET /encounters/{id}`); если врач не участник того приёма и сервер ответит 403, блок покажет «Показателей пока нет». Для сводки по всем приёмам понадобился бы эндпоинт «наблюдения пациента».
4. **«Ближайший приём»** читается из журнала врача на 30 дней (одна страница 50 записей), то есть показывает только приёмы с этим врачом. Эндпоинта «записи пациента» для врача нет.
5. Сводка и назначения по приёму считаются по первой странице назначений (10 шт.): у пациента с длинной историей в раскрытой карточке старого приёма назначения могут не показаться (полный список с пагинацией остаётся ниже).
6. Токен `--destructive-soft-hover` после удаления `danger` не используется в компонентах (на него ссылается только `globals-contrast.spec.ts`); оставил, чтобы не трогать V1.
