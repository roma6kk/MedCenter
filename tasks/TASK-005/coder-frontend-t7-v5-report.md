## Auth-service (backend)

- `login-page.ts`: новая вёрстка, inline-CSS и inline-скрипт (только переключатель пароля) закреплены в CSP по sha256; добавлены `script-src 'sha256-…'` и `font-src 'self'`, остальное прежнее (`default-src 'none'`, `frame-ancestors 'none'`, без `unsafe-inline` и внешних адресов). Шрифты — Onest Variable (SIL OFL), подмножества cyrillic и latin из пакета `@fontsource-variable/onest`, лежат как base64 в `login-fonts.ts` и отдаются контроллером `LoginAssetsController` по `GET /oauth/assets/fonts/{onest-cyrillic|onest-latin}.woff2` (`Cache-Control: immutable`, 404 для любого другого имени, из Swagger исключён). Внешние CDN не используются.
- `login-page.responder.ts`: `siteUrlFor(redirectUri)` для ссылки «← На сайт».
- Тесты: `login-page.spec.ts` (+ дизайн, хеши CSP совпадают с реальным содержимым страницы, нет «забыли пароль»), `login-assets.controller.spec.ts`.

## Вопросы владельцу

1. **«Забыли пароль?»**: в auth-service нет сброса пароля, ссылка не добавлена. Нужен ли сброс (e-mail-транспорт, токены) как отдельная задача?
2. **Кабинет врача на профиле**: `GET /rooms` закрыт токеном. Открыть публично кабинет (или отдавать его в DTO врача) — решение по бэкенду.
3. **Описание врача (стаж, образование)**: в API нет полей; сейчас честная строка «клиника пока не публикует». Нужны поля в practitioner-service?
4. **Выход ведёт на `/`** вместо `/login`: подходит ли? (Иначе после выхода пользователь сразу видел бы форму входа.)
5. **Услуги врача** вычисляются N запросами `GET /doctors?serviceId=` (как в мастере записи, общий кэш); при росте каталога нужен эндпоинт «услуги врача».
6. **Слоты одной длительности у разных услуг** (30/30) на странице врача неразличимы: фильтр по длительности, как и в мастере записи; сервер по-прежнему проверяет пару.
7. **Брендовый шрифт на странице входа** встроен base64 в исходник auth-service (~70 КБ): допустимо, или вынести в отдельный статический каталог с настройкой сборки?
