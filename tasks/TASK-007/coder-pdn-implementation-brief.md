- Бельгийскую терминологию eHealth не упоминать. FHIR только R4 International.
- Не делать: функции интерпретации медданных, внешние CDN/шрифты/аналитику, «ЭМК/ЭМД», надписи «подписано» для записей врача.

## Пункты (раздел 4 обзора)

1. **B4.** `cancelReason` (отмена записи) и комментарий/причина при записи на приём → нейтральные коды без свободного текста: `plans-changed` («Изменились планы»), `inconvenient-time` («Неудобное время»), `other-doctor` («Выберу другого врача»), `other` («Другое»). Нет кода «плохое самочувствие». Проверка на сервере (appointment-service DTO), маппинг в FHIR R4 (`Appointment.cancelationReason` как CodeableConcept с локальной системой), фронт — радиокнопки/select. Старые данные со свободным текстом отображать как «Другое».
2. **B3.** Серверная проверка 18+ при саморегистрации (auth-service, ошибка `AGE_RESTRICTED`, сообщение на фронте); в форме согласия для пациента < 18 нет варианта `consenterType = self` (сервер patient-service + фронт).
3. **D1 п. 3.7.** Таймаут бездействия сессии: после N минут без активности (конфиг, по умолчанию 15) — выход с сообщением; на сервере — idle-проверка refresh/сессии, если архитектура позволяет.
4. **D3.** События аутентификации (успешный вход, неудачный вход, выход, блокировка, смена/сброс пароля) → FHIR `AuditEvent` type `http://dicom.nema.org/resources/ontology/DCM|110114` (User Authentication), subtype `110122 Login` / `110123 Logout`, outcome 0/4; тем же механизмом, что существующий аудит auth-service.
5. **B1, C3.** Чекбокс регистрации не предзаполнен, время и версия текста сохраняются (проверить — уже частично есть из TASK-003). Страница учебной политики обработки ПДн (`/privacy`): шапка «оператор вымышлен — учебный проект», цели → ПДн → основание → срок; cookie (только технические, сроки = коду); права субъекта; «трансграничной передачи нет». Ссылка в футере и у чекбокса; версия политики хранится при согласии. Без cookie-баннера.
6. **C2.** «Удалить учётную запись» в ЛК пациента: деактивация пользователя (не удаление мед. ресурсов), отзыв refresh-токенов, `AuditEvent`, экран «что удалено / что хранится и почему».
7. **B2, A2.** PDF-образец согласия с водяным знаком «ОБРАЗЕЦ — вымышленные данные» в сиде демо (используется как скан согласия вместо реального). Убрать «ЭМК», «электронная медкарта», «медкарта» из UI — заменить на «История приёмов» / «Медицинские записи»; «Подписано {date}» для бумажного согласия пациента оставить допустимо (это бумага), но записи врача не называть подписанными.
