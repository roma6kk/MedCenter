## 2. Что я изменил (после аудита)

Найдено в браузере и исправлено:

1. **Сетка слотов расписания показывала «Слотов за период нет» у расписания с горизонтом в будущем.** Период по умолчанию был «сегодня + 14 дней», а слоты тестового расписания лежали в ноябре. Теперь сетка открывается на первых двух неделях горизонта (`defaultGenerationRange`, та же логика, что у диалога генерации). Тест: `should open at the first day of the horizon when the schedule starts after today`.
2. **Устаревшая ошибка импорта терминологии.** После 422 («версия не входит в поставку») правка версии снимала сообщение у поля, но под формой появлялся баннер `TERMINOLOGY_NOT_FOUND` из старого ответа. Теперь правка версии сбрасывает результат последней попытки (`start.reset()`). Тест: `should drop the old refusal when the version is edited after a 422`.
3. **Фокус при ошибке фильтров.** Формы периода и фильтров (аналитика, аудит, диалог генерации слотов) показывали ошибку, но оставляли фокус на кнопке. Теперь фокус переходит на первое некорректное поле (`shared/focus-field.ts`). Тесты: фокус в трёх спеках (audit-panel, analytics-panel, slot-generation-dialog).
4. **`<ul>` внутри `<p>` в мобильных карточках** (ошибка гидрации в консоли): `PaginatedTable` кладёт ячейку в `<p>`. Список окон недели в таблице расписаний теперь рендерится спанами; одно окно на строку без переноса времени. Мёртвый `summarizeWindows` удалён вместе с тестом.
5. **Цели нажатия 44 px.** `CONTROL_CLASS`, кнопки (primary, secondary, danger), действия в строках таблиц, чекбоксы ролей и «Учётная запись активна», кнопка «Копировать» — все `min-h-[44px]` (было 32–40). Действия строки расписания выстроены в столбец, чтобы четыре действия не вылезали за ширину таблицы на 1280 px.
6. **Чипы кодов растягивались на всю ячейку** (код НСИ в услугах, ссылки в пользователях): `justify-items-start` / `items-start`.
7. **Подсказки ресурса в аудите** урезаны до типов, которые реально есть в журнале: Appointment, AuthUser, CodeSystem, Condition, Encounter, Patient, PractitionerRole. Location, HealthcareService, Schedule, Slot, ServiceRequest, MedicationRequest, Observation на стенде дают 0 событий.

Общие файлы (lib/**, messages/**, components/layout|feedback|data-display) не менялись, новых ключей сообщений не требовалось.

## 5. Замечания к бэкенду (в `apps/` не правил)

1. `POST /api/v1/admin/rooms` принимает кабинет с уже существующим `identifier` и отвечает 201, хотя API-спек §4.4 называет идентификатор уникальным. Проверено: второй кабинет с `101` создался (я сразу переименовал и удалил его).
2. Нет эндпоинта списка `PractitionerRole`: `GET /doctors` отдаёт id `Practitioner`, а не роли. Поэтому для DOCTOR-аккаунта нельзя сделать выбор роли из списка, поле «Роль врача (PractitionerRole)» остаётся вводом FHIR id. Предложение: поле `roleIds` в `DoctorResponseDto` либо `GET /admin/practitioner-roles` со свободными ролями.
3. Создание, правка и удаление кабинетов, услуг и расписаний не порождают `AuditEvent` (фильтр журнала по Location, HealthcareService, Schedule, Slot даёт 0 событий). FR-021 покрывает только auth-, appointment- и encounter-сервисы.
4. Импорт терминологии завершается быстрее секунды, поэтому 409 `IMPORT_RUNNING` в браузере не воспроизвести одним оператором; поведение проверено только в jest.

Рекомендация оркестратору: у каждого агента строго уникальное имя сессии.
