# Расхождения фронтенда с API (вход для интеграции фронтенда)

Собрано оркестратором из отчётов бэкенд-агентов (WF-1…WF-6), 2026-10-16. Источник истины — `specs/api-designer-spec.md` и фактическое поведение сервисов (smoke `npm run smoke:stack`).

- **implement:patient**: frontend/ does not call API 3.1, 3.2 or 3.3. The doctor page /(doctor)/patients/[patientId] shows only /patients/{id}/history from encounter-service, although frontend-design-spec expects PatientHeader and RelatedPersons on it (API 3.2/3.3). The patient profile page uses /api/v1/me from auth-service, whose firstName/lastName names match PatientResponseDto. Nothing was changed in frontend/.
- **implement:analytics**: frontend/src/components/admin/audit-table.tsx requests only `/api/v1/admin/audit?page=N` with no from/to. The service defaults to the last 30 days, so older log entries can't be reached from the UI.
- **implement:analytics**: audit-table.tsx shows and copies requestId, but it is always '' because no service records it in AuditEvent (see deviations).
- **implement:analytics**: analytics-dashboard.tsx reads only the flat booked/cancelled/noshow fields of 9.1. These are returned alongside the MeasureReport groups[], so it is compatible. 9.2 and 9.3 have no UI yet.
- **implement:catalog-gaps**: frontend/src/components/booking/slot-picker.tsx calls GET /api/v1/schedules/{scheduleId}/slots?status=free. The spec has no such path and Traefik has no /api/v1/schedules router, so it gets a 404. BookingWizard passes doctorId as scheduleId. It should call GET /api/v1/doctors/{doctorId}/slots?from=&to= (API 5.2.8). The 5.2.8 items carry id, start and status, so they fit the frontend Slot type.
- **implement:catalog-gaps**: frontend/src/components/admin/schedule-editor.tsx posts {days, horizonDays:30} to POST /api/v1/admin/schedules. CreateScheduleDto (5.2.1) requires practitionerRoleId, roomId, serviceId, horizonFrom, horizonTo, windows[] and slotDurationMin, so this returns 400 VALIDATION_ERROR.
- **implement:catalog-gaps**: frontend/src/components/admin/slot-generation-dialog.tsx posts an empty body {} to /admin/schedules/{id}/generate, and admin/schedules/page.tsx hard-codes scheduleId='default'. GenerateSlotsDto (5.2.5) requires from and to, so this returns 400.
- **implement:catalog-gaps**: frontend/src/app/(admin)/admin/rooms/page.tsx calls GET /api/v1/admin/rooms?page=. The spec route is GET /api/v1/rooms (4.3). Traefik sends /admin/rooms to practitioner-service, which has no GET handler, so it gets a 404.
- **implement:catalog-gaps**: frontend/src/app/(admin)/admin/services/page.tsx calls GET /api/v1/admin/services?page=. Only the public GET /api/v1/services exists in catalog-service, so this gets a 404.
- **implement:catalog-gaps**: frontend doctors/page.tsx and doctors/[doctorId]/page.tsx expect {items:[{id,name,specialty}]}. practitioner-service returns a bare array of DoctorResponseDto with firstName and lastName and no `name`. The API 0 {items, meta} envelope is not followed on GET /doctors, GET /rooms and GET /services, but the admin tables read data.meta.
- **implement:catalog-gaps**: These match the contract: GET /api/v1/doctor/schedule ({items:[{id,label}]}) and GET /api/v1/admin/rooms/{id}/usage ({items:[{resourceType,id,display}]}).
- **implement:encounter**: CRITICAL: the doctor journal link 'Открыть приём' (frontend/src/app/(doctor)/doctor/appointments/page.tsx) goes to /encounters/{appointmentId}, and EncounterView then calls GET and POST .../complete with that appointment id. The API expects an Encounter id created by POST /api/v1/encounters {appointmentId} (7.1), which the frontend never calls, so that id returns 404. Fix on the frontend: call POST /api/v1/encounters on click (200/201, idempotent) and navigate to /encounters/{response.id}.
- **implement:encounter**: /me/prescriptions and /patients/{id}/prescriptions return ServiceRequest items too (kind: 'service', no atcCode), as spec 7.5 requires. The frontend Prescription type only knows atcCode/dosageText/note, so service items render with an empty ATC chip; the frontend needs to branch on `kind`.
- **implement:encounter**: EncounterView reads only `status` from GET /encounters/{id}. The API also returns summary, recommendations, diagnoses[], observations[], serviceRequests[] and medicationRequests[] in CompleteEncounterDto field names, so the read-only form can be filled directly.
- **implement:encounter**: The frontend sends an Idempotency-Key header on POST .../complete; the service ignores it (replay gives 409 ENCOUNTER_STATE_INVALID, which the frontend already handles as the read-only banner).
- **implement:appointment**: Patient list: frontend/src/app/(patient)/appointments/page.tsx calls GET /api/v1/me/appointments. The spec 6.2 and Traefik route /api/v1/appointments, and Traefik has no /api/v1/me/appointments route, so this would 404 at the edge. Implemented per spec.
- **implement:appointment**: Appointment detail: frontend/src/components/appointments/appointment-detail-view.tsx calls GET /api/v1/me/appointments/{id}. The spec 6.3 is /api/v1/appointments/{id}. Implemented per spec.
- **implement:appointment**: Doctor journal: frontend/src/app/(doctor)/doctor/appointments/page.tsx calls GET /api/v1/doctor/appointments?date=YYYY-MM-DD and reads items {id, time, patientName, status}. The spec uses from/to and returns AppointmentViewDto (start, patientName, ...). 'date' is not a declared DTO field and is dropped by the whitelist, so the page would receive every appointment and no 'time'. The frontend should send from=to=YYYY-MM-DD and derive the time from 'start'.
- **implement:appointment**: frontend/src/components/appointments/appointment-card.tsx reads doctorName and serviceName. These are provided by AppointmentViewDto on 6.2 and 6.3. Responses of 6.1, 6.4 and 6.6 (AppointmentResponseDto) do not include them, and the frontend only uses their id.
- **fixfirst:analytics**: analytics-dashboard.tsx шлёт from/to как YYYY-MM-DD (input type=date): совместимо со строгим RFC 3339 паттерном. Контракт плоских booked/cancelled/noshow сохранён
- **fixfirst:analytics**: audit-table.tsx запрашивает только ?page=N: сервис берёт последние 30 дней, более старые события таблица не покажет, пока в UI нет полей периода (без изменений)
- **fixfirst:analytics**: У событий appointment-/encounter-service requestId пустой, а кнопка копирования в audit-table.tsx копирует пустую строку: нужно писать entity.detail requestId в этих сервисах (события auth-service уже несут XrequestId)
- **implement:auth#1**: frontend/src/components/admin/terminology-import-panel.tsx posts {} (no snapshotVersion) to /api/v1/admin/terminology/import and expects 202 or 409. The spec requires { snapshotVersion } and the endpoint is not served, so the panel currently gets 404. When it is added, snapshotVersion should be optional.
- **implement:auth#1**: frontend/src/app/(auth)/register: a duplicate email arrives as errorCode CONFLICT, which errorCodeMap shows as the generic banner with detail 'EMAIL_TAKEN: a user with this email already exists'. There is no dedicated email-field hint.
- **implement:auth#1**: frontend/src/app/api/auth/authorize/route.ts requests offline_access, which the client is not granted, so it is silently dropped (no effect on the flow). Its default AUTH_BACKEND_URL (http://auth-service:3000) is an internal host on the wrong port; docker-compose.yml overrides it to http://medcenter.localhost:8081, so the flow works in the stack.
- **implement:auth#1**: API 2.1.3 example shows patient as 'Patient/9f2c...' but the contract and the frontend (patientRef ?? patient) use the bare id. The service follows the contract.
- **implement:auth#1**: Additive response fields name, role and practitionerRoleRef on UserResponseDto match what frontend UserRow (users-table.tsx) renders. The paginated items and meta envelope matches.
- **seed**: frontend/src/app/(public)/doctors/page.tsx reads { items: [{ name, specialty }] } from GET /api/v1/doctors, but practitioner-service returns a bare array of { id, firstName, lastName, specialty } and never fills roomId, although the seed sets PractitionerRole.location and Practitioner.name[0].text. I did not edit frontend/.
- **fixfirst:catalog-gaps**: slot-picker.tsx calls GET /api/v1/schedules/{scheduleId}/slots?status=free, which is not in the spec and has no Traefik route. It should call GET /api/v1/doctors/{doctorId}/slots?from=&to= (5.2.8). BookingWizard already passes doctorId, and the response items {id,start,status} match the frontend Slot type. - **implement:auth#2**: frontend/src/components/admin/terminology-import-panel.tsx POSTs /api/v1/admin/terminology/import with body {}; the spec (and this service) requires {"snapshotVersion":"1.4.463"}, so the panel gets 400 VALIDATION_ERROR, and its onError only handles 409 (shows nothing on 400).
