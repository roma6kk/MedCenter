### Сценарий C2 (повторный complete)

- Один приём в двух вкладках. Во второй вкладке завершили. В первой вкладке (на момент возврата форма уже была перерисована по refetch при фокусе окна) приём стал read-only с содержимым второй вкладки, баннер получил фокус.
- Чтобы получить настоящий 409, refetch `GET /encounters/{id}` в первой вкладке заблокирован (`network route --abort`). Отправка устаревшей формы: `POST …/complete` 409 `ENCOUNTER_STATE_INVALID`. После снятия блокировки и повторной отправки: 409, затем read-only со **сохранённым содержимым второй вкладки** («вкладки 2 (победила)»), а не с тем, что набрано в первой. Баннер получает фокус.

### Неявка

`POST /doctor/appointments/{id}/noshow` 200 (по клавиатуре: Enter на «Неявка» открывает подтверждение с фокусом на «Подтвердить неявку»; Escape отменяет и возвращает фокус на «Неявка»; Enter подтверждает). После: журнал перезапрашивается, статус НЕЯВКА, фокус на ссылке пациента этой строки, тост «Неявка отмечена» (`role=status`).

### Журнал, расписание, страница врача

- `/doctor` → `/doctor/appointments`. Невалидный `?date=` (`abc`, `2026-13-45`, `2026-02-30`) → сегодняшний день. День синхронизируется с адресной строкой (`?date=…`). Кнопки «←», «→», «Сегодня», поле даты, фильтр статуса работают; фильтр клиентский, при нескольких страницах показывается подсказка.
- Расписание: `GET /doctor/schedule?from=2026-10-17&to=2026-10-30` 200, окна недели, слоты по дням («занято N из M»), «Раньше/Позже/Сегодня», пустое состояние «В этом периоде слотов нет».
- Связанные лица: в сидах пусто («Доверенных лиц нет»); отрисовка проверена подменой ответа `/related` (`network route`): имя, родство, `tel:` и `mailto:` — ссылки, поле url типа `javascript:` остаётся простым текстом.
- EN-локаль: журнал, расписание, приём и карточка переведены; кириллица остаётся только в данных API и в `schedule.comment` (см. F-8).
- 375 px: журнал — карточки, форма приёма, read-only приём, карточка пациента, расписание: горизонтальной прокрутки нет (`scrollWidth == clientWidth == 375`).
- Консоль: ошибок и предупреждений нет (кроме Fast Refresh). Все 4xx/5xx в сетевом журнале — преднамеренные проверки (409, 422, 404, 403 по чужим id) и один 401 на мой собственный `fetch` без токена.
- Клавиатура: порядок Tab логичен, фокус виден везде (outline 2px `rgb(15,118,110)`), у кнопок и полей высота 44 px; Escape закрывает список ICD-10 без потери введённого; Enter при активной подсказке выбирает её.

## 4. Находки

### Major

**F-1. Enter в однострочном поле необратимо завершает приём без подтверждения.**
Страница `/encounters/{id}` (в работе). Шаги: заполнить заключение, рекомендации, выбрать диагноз (J06.9), поставить фокус в «Название диагноза 1» и нажать Enter. Результат: `POST /encounters/2831/complete` 200, приём становится read-only навсегда. То же для «Дозировка», «Примечание» и для combobox ICD-10/АТХ, когда список открыт, но активной подсказки нет (Enter отправил форму; остановила её только клиентская валидация). Приём завершается атомарно и без возможности исправления, поэтому случайный Enter в последнем заполняемом поле портит клинический документ. Рекомендация: отдельный шаг подтверждения перед `complete` либо блокировка неявной отправки в `input` (отправка только по кнопке «Завершить приём»).

**F-2. Запись остаётся `booked` после завершения приёма, бэкенд принимает «неявку» для такого визита (проблема бэкенда).**
Журнал `/doctor/appointments?date=2026-10-22`: после `complete` (приём 2777 завершён) запись 2773 по-прежнему «ЗАПИСАН», с кнопками «Открыть приём» и «Неявка»; ответ `GET /doctor/appointments` содержит `"status":"booked"`. `grep fulfilled` по `apps/` и `libs/` находит только тип статуса (`appointment.mapper.ts`) и список статусов доступа `CARE_APPOINTMENT_STATUSES` (`booked`, `arrived`, `checked-in`, `fulfilled`) в двух `patient-access.service.ts`: ничто не выставляет `fulfilled`, `appointment-service` не потребляет `encounter.completed.v1`. Дальше хуже: на визите с завершённым приёмом (запись 2801, приём 2805) «Неявка» вернула `POST …/noshow` 200 и статус НЕЯВКА при законченном приёме. Фронтенд смягчает только «Открыть приём» (409 → завершённая запись через историю). Требуется: бэкенд переводит запись в `fulfilled` по завершении приёма и отклоняет `noshow` для записи с завершённым приёмом (409 `ENCOUNTER_STATE_INVALID`).

### Minor

**F-3. После удаления строки фокус уходит на `body`.**
Форма приёма: «Добавить диагноз/наблюдение/лекарство», затем «Удалить диагноз 2» / «Удалить наблюдение 1» / «Удалить лекарство 1»: `document.activeElement` становится `BODY` во всех случаях. Пользователь клавиатуры или скринридера теряет место (WCAG 2.4.3). Фокус при добавлении строки ставится корректно (в первое поле новой строки).

**F-4. Обязательные поля не помечены.**
`summary`, `icd10-N`, `diagnosis-display-N`, `recommendations` обязательны по `CompleteEncounterDto`, но без `aria-required`/`required` и без визуального маркера; о требовании пользователь узнаёт только после отправки (WCAG 3.3.2).

**F-5. Ссылка на пациента в журнале ведёт на «Не найдено» для пациентов без активных записей к этому врачу.**
`/doctor/appointments?date=2026-10-22`, ссылка «Лебедева Анна» (`/patients/1442`): все четыре запроса страницы дают 403 `COMPARTMENT_VIOLATION: patient is outside the caller compartment`, страница показывает «Пациент не найден». У этой пациентки у Ивановой только отменённые записи. Причина в коде бэкенда: компартмент врача строится по записям в статусах `booked`/`arrived`/`checked-in`/`fulfilled` (`CARE_APPOINTMENT_STATUSES` в `patient-access.service.ts`), `cancelled` и `noshow` в него не входят. Журнал при этом показывает ссылку и в отменённых строках. Рекомендация: не делать имя ссылкой для `cancelled` (или показывать пояснение).

**F-6. Один и тот же `<title>` на всех страницах врача.**
`/doctor/appointments`, `/doctor/schedule`, `/encounters/{id}`, `/patients/{id}` — «Медицинский центр» (у входа есть «Вход — МедЦентр»). В `(doctor)` нет ни одного `metadata`. WCAG 2.4.2.

**F-7. Единица UCUM по умолчанию `Cel` для любого нового наблюдения.**
«Добавить наблюдение» → единица уже `Cel — градус Цельсия`; выбор «20001 — Рост», «20003 — Артериальное давление» единицу не меняет. Если врач не тронет селект, запись «Рост 170 Cel» уйдёт на сервер (проверка кода к единице на бэкенде не проверялась). Рекомендация: единица по умолчанию по показателю (20001→cm, 20002→kg, 20003→mm[Hg], 20004 и 20005→/min, 20006→Cel, 20007→%) либо пустая и обязательная.

**F-8. Заголовок карточки расписания — сырой `schedule.comment` с кодами RRULE.**
`/doctor/schedule`: «Приём терапевта (первичный), Кабинет 101: MO/TU/WE/TH/FR 09:00-13:00 (время клиники, Минск)» — текст бэкенда, не локализуется (в EN остаётся русским), содержит `MO/TU/WE/TH/FR`. Источник: `schedule-windows.tsx:31` (`schedule.comment ?? t('scheduleFallback')`). Рекомендация: собирать заголовок из услуги и кабинета.

**F-9. Самостоятельные ссылки меньше целевого размера.**
`К журналу` 77×17, «Открыть приём» в истории и назначениях 108×19, имя пациента в журнале 65×39 и 104×19 (при переносе). Спека §7 требует 44 px; даже порог WCAG 2.2 SC 2.5.8 (24 px) не выполнен для самостоятельных ссылок. Кнопки действий и поля формы — 44 px, это в порядке.

**F-10. Повторяющиеся accessible-имена без различителя.**
В журнале три кнопки «Отметить неявку: Кузнецов Павел» без времени (у «Открыть приём» время есть). На карточке пациента 8 одинаковых ссылок «Открыть приём с назначением: Азитромицин» без даты (у истории дата в имени есть).

### Nit

- **Два «Перейти к содержимому»** в порядке Tab (ссылки на `#main` и `#main-content`), избыточная остановка, каркас StaffShell/корневой layout, не область врача.
- **409 при заблокированном refetch:** баннер показывает сырой английский `detail` («encounter is finished, only an in-progress one can be completed (BR-003)») внутри русского интерфейса, баннер расположен под формой (вне экрана), фокус остаётся на `body`. В обычном случае refetch сразу даёт read-only, поэтому крайний случай.
- **Dev-режим:** первая навигация на `/encounters/{id}` после «Открыть приём» занимала ~15 с (холодная компиляция маршрута). Кнопка после ответа POST снова активна и без «Открываю…», пока идёт `router.push` — возможен повторный клик. Первый клик по «Расписание» тоже не навигировал несколько секунд. В продакшен-сборке не проявится.
- **Карточка пациента недоступного пациента** отправляет 4 параллельных запроса, и все возвращают 403; три зависимых запроса можно не отправлять, пока шапка не загрузилась.
- **«К журналу»** ведёт на журнал сегодняшнего дня, а не на день визита (кнопка «Назад» браузера работает).
- **Пустое поле ICD-10** даёт «Некорректный код МКБ-10, например J06.9» вместо «Поле обязательно».
- **Подпись таблицы** «Записи на пятница, 23 октября» (именительный падеж вместо «на пятницу»); заголовок дня без года («пятница, 1 января» для 1999 года).
- **Название услуги расходится:** в шапке приёма «Приём первичный терапевта» (display НСИ, `serviceType.display` из API), в журнале и мастере — «Приём терапевта (первичный)» (данные бэкенда/сидов).
- **Legend «Наблюдения (витальные показатели)» на 375 px** переносится и перекрывает рамку fieldset (косметика).
- **Название диагноза редактируется независимо от кода:** в истории пациента встречается код J06.9 с названием «Dependence on enabling machines»; бэкенд сохраняет что угодно. Продуктовый вопрос.
- **Будущие даты:** «Открыть приём» и «Неявка» доступны для записей на 22–26 октября при сегодняшнем 17 октября; бэкенд принял оба действия (спека ограничивает только статус). Продуктовый вопрос.

### Замечание по бэкенду вне F-2

- **Порядок `GET /patients/{id}/prescriptions`:** сначала все `medication`, затем все `service`, а не по дате назначения (услуга 10008 от 17 октября оказалась на странице 2 после лекарств от 15 октября, остальные услуги на страницах 3 и 4). Хронологии на карточке пациента нет. Не нарушает спеку явно, минимальная серьёзность.

## 5. Не проверялось

- Список связанных лиц на живых данных (в сидах их нет; отрисовка проверена подменой ответа).
- `VALIDATION_ERROR` с `details[]` от сервера: клиентская валидация зеркалит DTO, и серверный 400 из формы не воспроизводится (покрыто юнит-тестом `encounter-problem-fields.spec.ts`).
- Silent refresh при 401 и `RATE_LIMITED` в области врача.
- Печать (print CSS).
