## 3. Замечания

Формат: `[серьёзность] заголовок` — файл:строка — суть — как исправить.

### Существенные

**1. [Существенно] Форма пользователя молча не отправляется, если у врача с привязанной PractitionerRole снять роль DOCTOR**

`frontend/src/components/admin/users/user-schema.ts:36-38`, `user-fields.tsx:69-73`, `user-form-dialog.tsx:45-47,54,67-69,78`.

`checkRoleRules` требует пустой `practitionerRoleId`, если среди ролей нет `DOCTOR`, а поле рисуется только при отмеченной роли `DOCTOR`. В форме редактирования врача с привязкой (`PractitionerRole/abc`) снимаем «Врач», ставим «Администратор», жмём «Сохранить»: ошибка принадлежит скрытому полю, её никто не показывает. Воспроизведено одноразовым jest-зондом: 0 вызовов `apiFetch`, 0 `role="alert"`, активный элемент остаётся кнопкой «Сохранить». Тот же тупик в форме создания: ввёл id, затем снял «Врач» (значение остаётся в состоянии RHF). Нарушает WCAG 3.3.1 и функционально не даёт понизить врача, пока администратор не догадается вернуть роль, очистить скрытое поле и снять роль заново. Проверка `practitionerRoleId` по `FHIR_ID_PATTERN` у скрытого поля устроена так же.

Исправление (лучше первый вариант): при снятии `DOCTOR` сбрасывать `practitionerRoleId` в `''` (`setValue` в `onChange` чекбокса роли), а для редактирования отправлять `null` (это уже умеет `linkChange`); либо считать правило ошибкой только пока поле показано; либо выводить ошибки скрытых полей в общем баннере формы. Добавить тест «should release the PractitionerRole link and send the patch when DOCTOR is unchecked on a linked doctor».

**2. [Существенно] Сетка слотов выдаёт усечённый ответ за полный: «Всего слотов: 20» (корень в бэкенде)**

`frontend/src/components/admin/schedules/schedule-slot-grid.tsx:29-36,88-95`; причина `apps/catalog-service/src/modules/schedules/schedules.service.ts:199-205`.

`listSlots` делает один `fhirClient.search('Slot', …)` без `_count` и без чтения следующих страниц (`HttpClient.search` возвращает одну страницу Bundle), хотя в `catalog-service/src/common/fhir-search.ts` уже есть `readAllPages`, а публичный поиск слотов листает до 50 страниц. Независимая проверка в браузере (`browser-verify-frontend-admin-report.md`, A-1) показала на сидовом расписании ровно 20 слотов в админской сетке против 137 в публичном `GET /doctors/{id}/slots` за тот же период. Я воспроизвёл причину чтением кода; сам стенд не запускал. Итоги в шапке («Всего слотов: N · свободно · занято»), состояние «Слотов за период нет» и сценарий D (слоты видны после генерации) становятся недостоверными для любого периода дольше пары дней, а клиент об этом не предупреждает.

Исправление на бэкенде: листать все страницы (`readAllPages`) и отдавать признак усечения, как в публичном поиске. Исправление на клиенте, пока бэкенд не поправлен: если ответ пришёл ровно из 20 элементов, показывать предупреждение «возможно, показана только часть» и не печатать итог как точный. Записать в `backendIssues`.

**3. [Существенно] На 375 px страницы «Терминология» и «Аналитика» прокручиваются по горизонтали целиком (WCAG 1.4.10 Reflow)**

`frontend/src/components/admin/terminology/terminology-panel.tsx:18`, `analytics/analytics-panel.tsx:27,31`, `terminology/value-set-table.tsx:20`, `analytics/group-table.tsx:57`.

Контейнеры `grid gap-5` / `grid gap-4 lg:grid-cols-2` не задают колонку, поэтому единственная неявная колонка имеет `min-width: auto`, и секция растёт до ширины таблицы; обёртка `overflow-x-auto` вокруг таблицы никогда не срабатывает. Независимая проверка в браузере дала `scrollWidth` 717 при ширине 375 для терминологии и 409 для аналитики. Механизм я воспроизвёл на статической странице: при той же структуре обёртка получает 635 px при контейнере 343 px, при `grid-template-columns: minmax(0, 1fr)` ровно 343 px, и таблица прокручивается внутри обёртки. Кроме того, таблица ValueSet не превращается в карточки, хотя §D требует карточный вид на `<768px` (остальные страницы области используют `PaginatedTable` с карточками). Заявление реализатора «390 px без горизонтальной прокрутки» верно только для проверенных им страниц.

Исправление: `grid-cols-[minmax(0,1fr)]` (или `min-w-0` у секций) в обоих контейнерах; для ValueSet использовать `PaginatedTable` с карточками либо оставить прокрутку внутри таблицы.

### Незначительные

**4. [Незначительно, новое] Старый баннер ошибки всплывает с `role="alert"`, как только пользователь начинает править поле с серверной ошибкой**

`users/user-form-dialog.tsx:54,78`, `services/service-form-dialog.tsx:83`, `rooms/room-form-dialog.tsx:66`, `schedules/schedule-editor.tsx:88`, `shared/apply-server-error.ts:33-36`.

Баннер показывается при `mutation.isError && !hasServerFieldError(errors)`. После 409 `EMAIL_TAKEN` ошибка стоит у поля email, баннера нет. Но при первом же вводе в поле RHF перепроверяет его, снимает серверную ошибку, `hasServerFieldError` становится `false`, а `mutation.isError` всё ещё `true`: под формой появляется `role="alert"` со старым «Пользователь с таким email уже существует», пока человек печатает новый адрес. Воспроизведено jest-зондом (баннеров до правки 0, после 1, алертов 1). Так ведут себя все формы области (email, роль врача, код НСИ, поля из `details[]`).

Исправление: сбрасывать мутацию (`mutation.reset()`) при снятии серверной ошибки с поля или хранить в состоянии формы «показанную» ошибку баннера, которая выставляется только когда ни одно поле не приняло ошибку. Добавить тест «should not show the stale banner when the email is edited after EMAIL_TAKEN».

**5. [Незначительно] Нет маршрута `/admin` (спека §1: `/admin` → `/admin/analytics`)**

`frontend/src/app/(admin)/admin/` не содержит `page.tsx`, тогда как `(doctor)/doctor/page.tsx` с редиректом есть. Прямой переход на `/admin` даёт 404 без каркаса персонала. Исправление: `app/(admin)/admin/page.tsx` с `redirect('/admin/analytics')` и тест по образцу врачебного.

**6. [Незначительно] У всех семи страниц один и тот же `<title>` (WCAG 2.4.2, уровень A)**

`frontend/src/app/(admin)/admin/*/page.tsx` не экспортируют `metadata`; публичные страницы, вход и мастер записи заголовки задают. Вкладки аналитики, пользователей, услуг, кабинетов, расписаний, терминологии и аудита неразличимы. Проблема сквозная (кабинеты пациента и врача тоже), решение общее: `metadata` на каждой странице или установка `document.title` из `useT`.

**7. [Незначительно, новое] Очистить комментарий расписания при правке нельзя: пустой комментарий не уходит, сервер оставляет старый**

`schedules/schedule-schema.ts:153-161` (строка 160), бэкенд `schedules.service.ts:91`.

`toUpdateSchedulePayload` исключает пустой `comment` («FHIR не хранит пустые строки»), а сервер меняет комментарий только при `dto.comment !== undefined`. Админ стирает текст, жмёт «Сохранить», получает тост «обновлено», а старый комментарий возвращается. Для кабинетов и услуг тот же случай решён иначе: правка всегда шлёт описание, пустое очищает (`room-schema.ts:35`, `service-schema.ts:67`). Теста на правку с пустым комментарием нет. Исправление: при правке всегда отправлять `comment` (как у кабинетов), либо проверить поведение HAPI и сделать пустое значение осмысленным, плюс тест.

**8. [Незначительно, новое] Поле «Коды специальностей» в форме услуги ни на что не влияет: сервер принимает его и отбрасывает**

`services/service-form-dialog.tsx:57-59`, `service-schema.ts:23,44,61,68`; бэкенд `catalog-service/.../create-service.dto.ts:35`, `services.service.ts` (`specialtyCodes` нигде не читается; `toHealthcareService` его не пишет).

Администратор вводит коды, получает «услуга создана», но коды не сохранены. При правке поле всегда пустое («коды не показываются»), так что видеть или менять сохранённое невозможно. Спека 5.1.3 объявляет поле, фронтенд следует спеке, но функция не реализована в сервисе. Записать в `backendIssues`; до реализации скрыть поле либо пометить подсказкой, что значение пока не сохраняется.

**9. [Незначительно, новое] Импорт терминологии шлёт `Idempotency-Key`, которого сервер не знает; любой 409 трактуется как «импорт уже выполняется»**

`terminology/use-terminology.ts:28-33`, `terminology-import-panel.tsx:31-37`, `terminology/import-outcome.tsx:47`; бэкенд `auth-service/.../admin-terminology.controller.ts`.

Спека §0 называет идемпотентными только `POST /appointments` и генерацию слотов; контроллер импорта заголовок не читает. Хук ключа, заголовок и тест на него ничего не дают и создают впечатление защиты, которой нет (в прежнем отчёте это названо достоинством). Заодно `problem.status === 409` шире, чем `IMPORT_RUNNING`: любой другой 409 будет показан как «уже выполняется». Исправление: убрать ключ из импорта, а `AlreadyRunning` показывать только при `detailCodeOf(problem) === 'IMPORT_RUNNING'`.

**10. [Незначительно] После удаления последней записи на последней странице список показывает «пусто» без пейджера**

`rooms/rooms-panel.tsx:42-48`, `services/services-panel.tsx:43-60`, `schedules/schedules-panel.tsx:43-65`.

**11. [Незначительно] После успешных мутаций и ошибок вне полей фокус теряется на `body` (WCAG 2.4.3)**

`shared/form-actions.tsx:22`, `shared/confirm-dialog.tsx:38`, `shared/use-admin-mutation.ts:24-27`, `hooks/use-dialog-focus.ts:41-44` (общий файл).

Кнопка отправки становится `disabled` на время запроса и теряет фокус. `useAdminMutation` дожидается `invalidateFor` (список перерисован, кнопка-инициатор в строке исчезла: «Деактивировать» превратилась в «Активировать», удалённая строка пропала), и только потом вызывается `onClose`, который пытается вернуть фокус на уже удалённый элемент. Подтверждено независимой проверкой (A-5): фокус `BODY` после деактивации, удаления, генерации и 409 без полевой ошибки. Исправление: `aria-disabled` вместо `disabled` (или не терять фокус иным способом), после закрытия переводить фокус на заголовок страницы или контейнер списка.

**12. [Незначительно, новое] Формы области не применяют `RATE_LIMITED` (спека §5.4: блокировать отправку на `Retry-After`)**

Исправление: `useRetryCooldown(problemOf(mutation.error))` в `FormActions`/`ConfirmDialog` и у кнопок генерации и импорта.

**13. [Незначительно] Обязательность поля недоступна вспомогательным технологиям; ошибки группы и периода не связаны с полями**

`schedules/schedule-form-dialog.tsx:22-26`, `hooks/use-dialog-focus.ts` (общий файл).

`useDialogFocus` фокусирует первый элемент один раз при монтировании. Пока `pickers.isPending`, в диалоге только скелетон; когда редактор появляется, фокус уже не переносится и остаётся на кнопке за подложкой (Tab уходит из диалога). В обычном случае списки уже в кэше панели; проявляется при холодном открытии и медленной сети. Исправление: фокус на заголовке диалога (`tabIndex={-1}`), пока нет фокусируемых элементов, либо открывать диалог после загрузки списков. Заодно: при ошибке списков диалог показывает и баннер, и редактор с пустыми списками (`schedule-form-dialog.tsx:24-25`).

**15. [Незначительно] Серверные ошибки полей, которых нет в форме, теряются; баннер скрывается без причины**

`shared/apply-server-error.ts:26,33-36`, `schedules/schedule-editor.tsx:23`.

`applyProblemToForm` возвращает неузнанные сообщения именно для баннера, а `applyServerError` их отбрасывает; `ProblemBanner` при непустых `details[]` сам прячет `detail`. 400 с `details` на `windows.0.startTime` (поля `windows` нет в `FIELDS`) покажет только заголовок «Ошибка валидации» без причины. Обратная сторона: `hasServerFieldError` возвращает `true` для любой серверной ошибки, и баннер скрыт, даже если поле не показывает текст (`isActive` в `EDIT_FIELDS` не имеет места под ошибку). Клиентская проверка зеркалит серверную, поэтому на практике редко. Исправление: возвращать неузнанные сообщения из `applyServerError` в `AdminProblem`, `hasServerFieldError` считать только по реально показанным полям.

**16. [Незначительно] Расписания отключённых врачей подписаны сырым FHIR-id; выпадающие списки молча обрезаны сотней записей**

`schedules/use-schedule-pickers.ts:26,44-47`, `schedules/schedules-table.tsx:65`.

`pickers.doctors` включает только активные аккаунты DOCTOR, поэтому для расписания врача с деактивированным аккаунтом `labelOf` возвращает необработанный id (в таблице, в `aria-label` строк и в диалогах), а фильтр «Врач» такого врача не предлагает; тест `useSchedulePickers` закрепляет это как желаемое. `ALL_PAGE_SIZE = 100` без признака усечения: сто первый кабинет или услуга не появится в выборе. Исправление: для таблицы и фильтра брать всех врачей (неактивных помечать), для выбора при создании оставить активных; при `meta.totalItems > items.length` предупреждать или догружать.

**17. [Незначительно] Сетка слотов шлёт запрос без дат при очистке поля и не ограничивает период**

`schedules/schedule-slot-grid.tsx:55-74`, `schedules/use-admin-schedules.ts:89-94`.

Очистка `<input type="date">` даёт пустую строку, `withQuery` её выбрасывает, и запрос без `from`/`to` отвечает 400 (`ScheduleSlotsQueryDto` требует оба). Проверки порядка дат и максимума нет (в диалоге генерации она есть). Исправление: `enabled` у `useQuery` только при корректных датах и `from <= to`, подсказка у поля, разумный предел периода.

**18. [Незначительно] Диалог генерации слотов оставляет прошлый результат и прошлую ошибку после правки периода**

`schedules/slot-generation-dialog.tsx:46,72-73`.

После успеха «Создано слотов: 4, пропущено: 0» остаётся на экране, пока администратор меняет «С»/«По»; так же держится баннер прошлой ошибки. Это легко принять за итог нового периода. Исправление: `generate.reset()` в `onChange` дат (как уже сделано в панели импорта). Заодно: закрытие диалога во время генерации скрывает результат (успеха-тоста у `useGenerateSlots` нет).

**19. [Незначительно] Производительность и локаль форматтеров дат в сетке слотов**

`shared/admin-dates.ts:41-51`, `schedules/slot-grouping.ts`, `schedule-slot-grid.tsx:18-27`.

Исправление: форматтеры константами модуля, `useMemo` для группировки, локаль из `useUiStore`.

**20. [Незначительно, новое] В форме правки можно отметить роль «Пациент» у учётки без FHIR-пациента; сервер ответит сырым английским баннером**

## 4. Контекст-саммари

Область admin по структуре и контракту качественная: DTO и пути совпадают с кодом сервисов, ключи запросов и инвалидация соответствуют §5.1, коды ошибок §5.4 имеют отдельный UX и поведенческие тесты, i18n полон в обеих локалях, `tsc`, `jest` (35 наборов, 301 тест) и `next lint` зелёные, критичных проблем безопасности нет. Но есть три существенные проблемы: форма пользователя молча не отправляется после снятия роли DOCTOR у врача с привязкой (воспроизведено зондом), сетка слотов выдаёт первые 20 слотов за полный ответ (корень в `listSlots` бэкенда, клиент не предупреждает) и страницы терминологии и аналитики прокручиваются по горизонтали на 375 px (механизм воспроизведён). Остальное: новые находки (устаревший баннер при правке поля, комментарий расписания не очищается, поле специальностей услуги отбрасывается сервером, неиспользуемый `Idempotency-Key` в импорте, нет `/admin` и заголовков страниц), прежние замечания по фокусу, доступности и пагинации, а также недостающие E2E и принятые отклонения от спеки.
