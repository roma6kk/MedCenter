Ветка `feature/clinic-platform-wip`, клиент `frontend/` (отклонение от `apps/web` принято). Это второе возобновление: предыдущий исполнитель области оборвался по лимиту после написания почти всего кода и до отчёта. Я не переписывал рабочее: прошёл по заданию пункт за пунктом (код, spec-файлы, живой стек), добил недоделанное, исправил найденное в браузере и написал отчёт.

Владелец путей: `frontend/src/app/(doctor)/**`, `frontend/src/components/doctor/**`. В общих файлах (`messages/*.json`) сделаны только аддитивные правки в пространстве `doctor.*`.

## 2. Что я изменил в этом прогоне

### Исправления по результатам браузерной проверки

- **Фокус после завершения приёма.** Кнопка отправки исчезает, страница остаётся прокрученной вниз, баннер «Приём завершён» оказывается вне экрана. Это было видно и при своём complete, и при повторе (409). Теперь баннер получает фокус (`tabIndex=-1`, `role=status`) только в момент перехода «форма → запись». Открытие уже завершённого приёма фокус не забирает. Тесты: три новых в `encounter-view.spec.tsx`.
- **Фокус после неявки.** Кнопки действий исчезают из строки, фокус терялся на `body`. `useNoshow(onRecorded)` вызывает колбэк до обновления журнала, `NoshowButton` переводит фокус на ссылку пациента в той же строке (`data-row-anchor`, ищется в ближайшем предке, содержащем якорь: работает и в таблице, и в карточках на телефоне). Тесты: два новых в `noshow-button.spec.tsx`. Проверено клавиатурой вживую.
- **`VALIDATION_ERROR` с `details[]` не ставил фокус на поле.** Добавлена `firstPathOnScreen` (порядок секций, строк и полей как на экране) в `encounter-error-focus.ts`, `markServerProblem` фокусирует первое названное сервером поле формы. Тесты: шесть на функцию и один интеграционный (`encounter-complete-form-server.spec.tsx`).
- **Одинаковые ссылки «Открыть приём».** В истории и в назначениях пациента десятки ссылок с одним текстом (WCAG 2.4.4). Добавлен `aria-label` с датой визита или названием назначения (`doctor.history.openEncounterOn`, `doctor.prescriptions.openEncounterOn`, ru и en). Видимый текст остался началом доступного имени (WCAG 2.5.3).
- **Печатная выписка.** Глобальный `@media print` скрывает все `<header>`, поэтому «шапки» приёма и пациента пропадали бы при печати. `EncounterHeader` и `PatientHeader` стали `<section aria-labelledby>` с `h1`, ссылка «К журналу» помечена `no-print`. Печать в браузере не проверял (эмуляция media не сработала): вывод сделан по CSS.
- **Заголовки дней расписания.** `capitalize` поднимал регистр у каждого слова («19 Октября»). Заменено на заглавную только у дня недели; между заголовком и счётчиком «занято 15 из 17» добавлен пробел (иначе имя региона склеивалось).
- **EN-текст журнала** «Appointments today: N» показывался и для другой даты: теперь «Appointments on this day: N».

### Соответствие golden principles

Скриптом по AST проверены все файлы области: функции длиннее 30 строк, `any`, `!`, явные типы возврата, файлы длиннее 300 строк. Исправлено:
- `DiagnosisRow`, `DoctorJournal`, `DoctorScheduleView`, `JournalControls`, `TerminologyCombobox`, `ValueSetSelect` разбиты на небольшие компоненты и хуки (`useJournalState`, `useComboboxModel`, `DayPicker`, `PeriodControls`, `FallbackInput`, `OptionsSelect`, `DiagnosisCodeField`, `DiagnosisNameField`).
- У всех `forwardRef`-функций явный `: ReactNode`.
- `encounter-complete-form.spec.tsx` (332 строки) разделён на два набора плюс `encounter-form-test-utils.tsx`.
- Файлы с компонентом и значениями вызывали полную перезагрузку Fast Refresh (предупреждение в консоли браузера). Значения вынесены: `encounter-form-defaults.ts` (`EMPTY_*`), `encounter-form-helpers.ts` (классы, `errorAt`, `a11yOf`); лишние `export` убраны; `ATC_CODE_SYSTEM` заменён на `ATC_SYSTEM` из `encounter-problem-fields.ts`.
- Тяжёлые наборы (много набора текста через user-event) получили `jest.setTimeout(30_000)`: под нагрузкой машины первый тест падал по таймауту 5 с (в одиночном запуске проходил).

Остаток аудита: `encounterErrorMap` без явного типа возврата, но это константа с аннотацией `ZodErrorMap`; нарушением не считаю.

## 4. Браузерные доказательства (живой стек, `next dev` :3000, сессия `doctor`)

Вход: форма auth-service, `doctor.ivanova@medcenter.test`. Пароль читался из манифеста во время выполнения и нигде не печатался. Пациент `patient.kuznetsov@medcenter.test` бронировал через `POST /api/v1/appointments` (отдельная сессия `doctor-patient`, закрыта). Сессии закрыты.

**Сценарий C (J06.9, 36.6 Cel, J01FA10).**
1. Пациент записал слот 20.10 10:00 (201). В журнале врача на 20.10: строка «Кузнецов Павел, ЗАПИСАН», кнопки «Открыть приём» и «Неявка».
2. Клик → `POST /api/v1/encounters` 201 → `/encounters/2692` (id приёма, не записи). Повторный клик по другой записи: 201, затем 200 с тем же id (идемпотентность).
3. Пустая отправка: сообщения у полей, фокус на «Заключение». Форма заполнена: заключение, J06.9 (ввод «j06», стрелки, Enter: код и название подставились), наблюдение 20006 «Температура тела» 36.6 Cel, лекарство J01FA10 (выбор из подсказок «Азитромицин»), дозировка, рекомендации.
4. «Завершить приём» → `POST …/complete` 200 → read-only запись: баннер «Приём завершён. Запись доступна только для чтения.», шесть блоков, статус ЗАВЕРШЁН, окончание 11:33.
5. Перезагрузка: по-прежнему read-only (0 форм, 0 полей ввода).
6. Карточка пациента `/patients/1439`: шапка (дата рождения, возраст, пол, контакты), «Доверенных лиц нет», история (новый приём первым, ссылки на записи), назначения (Азитромицин J01FA10, ссылка на приём).

**Сценарий C2 (повтор).** Приём открыт в двух вкладках, во второй форма заполнена; в первой завершил, во второй нажал «Завершить»: `POST …/complete` 409 → форма заменена записью из хранилища, фокус на баннере.

**Остальное.**
- Повторное «Открыть приём» для завершённой записи: `POST /encounters` 409 → `GET /patients/1439/history` → переход на `/encounters/2692` read-only.
- Неявка: клавиатурой Enter, Enter (подтверждение): `POST …/noshow` 200, статус НЕЯВКА, тост «Неявка отмечена», фокус на ссылке пациента в той же строке. Escape возвращает фокус на «Неявка».
- Серверные ошибки на полях: J-код `Z99.9` → 422 `INVALID_ICD10_CODE`: поле помечено, фокус в нём, баннер с кодом и `requestId`. Неизвестный АТХ `A99ZZ99` → 422 `TERMINOLOGY_NOT_FOUND`: то же для поля АТХ.
- Английская локаль: журнал, форма, read-only запись, подписи кнопок. Мобильная вёрстка 375 px: журнал карточками, форма, баннер; горизонтальной прокрутки нет (`scrollWidth` = 375).
- Расписание `/doctor/schedule`: два расписания с окнами по дням недели, слоты на 14 дней по дням, занято и свободно.
- 404 и 403: `/encounters/99999999` и `/encounters/not-a-number` (404), `/patients/99999999` (403 `COMPARTMENT_VIOLATION`) показываются одинаково как «Приём/Пациент не найден»; на карточке пациента одно сообщение вместо четырёх.
- Клавиатура: порядок Tab по шапке и журналу, у фокуса обводка 2 px `rgb(15,118,110)`, цели действий 44 px.
- Консоль: ошибок нет. В сети 4xx только ожидаемые (409 повтор, 422 терминология, 403/404 несуществующие). Единственное постороннее: `GET /favicon.ico` 404 (core).

Скриншоты (рабочая папка скретча, не в репозитории): журнал 1280 и 375 px, пустая и заполненная форма, read-only запись, карточка пациента, расписание, EN-журнал, ошибка ATC на 375 px.

## 7. Замечания к бэкенду (без правок в `apps/`, `libs/`, `infra/`)

1. **Запись остаётся `booked` после завершения приёма.** В `AppointmentResponseDto` есть статус `fulfilled`, но ничего его не выставляет (`grep` по `apps/` пуст). Журнал врача продолжает предлагать «Открыть приём» и «Неявка» для уже оформленного визита. Фронтенд смягчает: повторное открытие ведёт на завершённую запись через историю.
2. **Неявку можно поставить записи, по которой приём уже завершён.** Проверено вживую: `POST /doctor/appointments/2686/noshow` → 200 при завершённом приёме 2692. Получается завершённый приём при записи «неявка». Ожидается 409 (BR-008). Побочный эффект проверки: запись 2686 в демо-данных теперь `noshow`.
3. `Idempotency-Key` на `POST …/complete` не поддерживается (как и отмечено ранее): повтор даёт 409, фронтенд это обрабатывает.

## 8. Открытые вопросы

- В демо-данных нет `RelatedPerson`: карточки доверенных лиц проверены только unit-тестами, живой ответ 3.3 пуст (200).
- Спека допускает офлайн-фолбэк ICD-10 и АТХ через `GET /terminology/validate` (2.3.3). Реализовано проще: ввод кода остаётся возможным при недоступных подсказках (показывается предупреждение), а проверку выполняет сервер при complete и возвращает ошибку на поле. Отдельного вызова validate нет.
- Заголовок вкладки у всех страниц врача общий («Медицинский центр»); это общий `metadata` корня (core), не область врача.
- Core: два одинаковых skip-link «Перейти к содержимому» подряд (корневой layout и `StaffShell`), ссылки навигации в `StaffShell` высотой 28 px (< 44 px), `GET /favicon.ico` отдаёт 404.
- Демо-данные, оставшиеся после проверки (все записи Кузнецова П. у врача Иванова, 20-21.10): приёмы 2692, 2722, 2730, 2752 завершены; записи 2711, 2760 и 2686 в статусе `noshow`; запись 2763 (21.10 09:30) осталась `booked`. Диагноз приёма 2722 подписан вручную неверно (код J06.9 с произвольным названием), это мой тестовый ввод.

### Для бэкенда (`backendIssues`, без правок в `apps/`)

1. После `POST /encounters/{id}/complete` запись остаётся `booked`; `fulfilled` не выставляется ни одним сервисом (appointment-service не слушает `encounter.completed.v1`). Журнал врача продолжает предлагать «Открыть приём» и «Неявка», фильтр «Состоялся» всегда пуст.
2. `POST /doctor/appointments/{id}/noshow` отвечает 200 для записи с завершённым приёмом (`markNoShow` проверяет только статус записи, `assertBooked`). Нужен 409 `ENCOUNTER_STATE_INVALID` (BR-008, API §1).
3. 422 `INVALID_ICD10_CODE` и `TERMINOLOGY_NOT_FOUND` называют коды только в тексте `detail`; для разметки полей нужен `details[{field,message}]`.
4. Текст пользовательского валидатора `atcCode must be an ATC code such as J01FA10` англоязычный и не локализуется клиентом; теперь недостижим из формы (маски выровнены), но придёт при прямых вызовах.
